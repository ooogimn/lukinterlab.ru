=== Git и деплой на сервер ===
Секреты в коде не хранятся — только в .env на машине (файл .env не в git). Репозиторий на GitHub лучше держать приватным до полной ротации ключей, если они уже светились в истории.

В проекте уже есть .gitignore и ветка main (git init выполнен один раз).
Локально, в каталоге lukinterlab.ru:
  git add -A
  git status
  git commit -m "Описание изменений"
  Если remote ещё не настроен — на GitHub/GitLab создать пустой приватный репозиторий, затем:
  git remote add origin <URL>
  git push -u origin main
  При ошибке "index.lock" — закрыть другие окна с этим репозиторием и удалить файл .git/index.lock, повторить git add.

На сервере (первый раз — клон в каталог сайта или отдельно + symlink):
  cd ~/domains/lukinterlab.ru
  git clone <URL> .          # если каталог пустой, или git init + remote add + pull
  # дальше при каждом обновлении:
  git pull origin main
  # Убедиться, что на сервере есть .env (или переменные в панели) с DJANGO_SECRET_KEY, DJANGO_DEBUG=False, ключами API.
  source <путь-к-venv>/bin/activate   # или свой способ активации venv на хостинге
  pip install -r requirements.txt    # при изменении зависимостей
  python manage.py migrate
  python manage.py collectstatic --noinput
  Перезапуск приложения (панель хостинга / touch tmp/restart.txt / gunicorn и т.д.)

Не коммитится (.gitignore): устаревшие db.sqlite3*, media/, static/ (собранная), .venv, логи. БД — только PostgreSQL (см. .env).

Автопостинг статей блога на стену сообщества VK (уже в коде: Blog/vk_utils.send_to_vk)
Это ОТДЕЛЬНЫЙ ключ от VK ID (сервисный/защищённый ключ приложения для wall.post не подходят).

1) Откройте сообщество как администратор → Управление → Настройки → Работа с API.
2) Создать ключ → отметить права «Стена», «Фотографии» → скопировать токен.
3) ID группы в settings: VK_GROUP_ID (сейчас 231035215; при другой группе замените или задайте VK_GROUP_ID в окружении).
4) На хостинге: в .env переменная VK_ACCESS_TOKEN=<токен> и перезапуск приложения (gunicorn/uwsgi/panel).
5) SITE_URL должен быть https://lukinterlab.ru (уже задан) — в пост идёт ссылка «Читать далее».
6) Пост уходит при первой публикации статьи (status=published), если vk_posted_at пусто. VK_AUTO_POST=True.

Проверка: опубликовать тестовую статью в админке → запись на стене группы; ошибки — в логах Django (VK wall.post).

MAX — API и автопост блога (код: Blog/max_utils.send_to_max, фон: django-q)
Официальная документация: https://dev.max.ru/docs-api
Хост API: https://platform-api.max.ru
Авторизация всех методов: заголовок Authorization: <access_token> (токен в query не поддерживается).
Токен: платформа MAX для партнёров → Чат-боты → Интеграция → Получить токен (аналогично business.max.ru в материалах MAX). Не разглашать.

Подготовка и настройка бота (MAX для партнёров)
  Подключение к MAX для партнёров и сервисам (чат-боты, мини-приложения, каналы) — для юрлиц и ИП-резидентов РФ. Уровень «с разработкой» — продвинутый; сценарии без кода — конструкторы («Бот без разработки» в доке).
  Создать бота можно при верифицированном профиле организации на платформе. На одну организацию — до 5 ботов. Пользователи получают доступ после успешной модерации; статус виден у названия бота.

Настройки бота в кабинете
  Имя в чате — задаётся при создании (поле «Название»). Аватар — логотип при создании. Ник — для публичной ссылки (например max.ru/<ник>; часто шаблон idИНН_bot), генерируется при создании; ник сейчас нельзя изменить. Описание — что бот умеет, польза, контакты/поддержка (поле «Описание»).
  Редактирование имени, аватара, описания — только на платформе партнёров, не в клиенте мессенджера. Можно запретить/разрешить добавление бота в групповой чат (по умолчанию запрет). Важно: если запретить группы — добавить бота в канал тоже не получится.

Токен бота
  После проверки бота: Чат-боты → Интеграция → «Получить токен» — уникальный ключ для вызовов API (бот считается зарегистрированным). Токен можно обновить при компрометации; в настройках можно привязать мини-приложение.
  Пример формата (не настоящий): AAHdqTcvCH1vGWJxfSeofSAs0K5PALDsaw — не хранить в открытом виде и не передавать третьим лицам.

Отправка запросов к API
  Бот шлёт HTTPS-запросы с токеном, ответы — JSON. Заголовок: Authorization: <token> (токен в query не поддерживается).
  Проверка: GET https://platform-api.max.ru/me с этим заголовком — в ответе данные бота (имя, ник и т.д.). Лимит нагрузки: ориентир ~30 rps на platform-api.max.ru. Детали методов — раздел «API» на dev.max.ru; для TS/JS — официальная «MAX Bot API» / репозиторий на GitHub.

Уведомления (Webhook или Long Polling — только один способ)
  Одновременно оба типа нельзя. Long Polling — удобен для разработки и тестов; для production рекомендуется Webhook.
  Подключение: POST /subscriptions с URL для входящих событий. Webhook: уточнить текущий endpoint у доки (в т.ч. GET /subscriptions). Только HTTPS (допускается самоподписанный сертификат), HTTP не поддерживается. Long Polling: GET /updates (см. актуальную документацию).

Диплинки (deep links)
  Формат: https://max.ru/<botName>?start=<payload>
  <botName> — ник бота; <payload> — до 128 символов; если длиннее — параметр боту не передаётся.
  Примеры: ?start=123; реферал ?start=ref_user456789; источник ?start=source_site.
  Несколько логических параметров — закодировать одной строкой в start, напр. param1_value1_param2_value2.
  Получение payload: через Webhook или Long Polling; для диплинка в настройках Webhook в update_types должен быть тип bot_started. Пример обновления:
  {"update_type":"bot_started","timestamp":1573226679188,"chat_id":1234567890,"user":{"user_id":1234567890,"name":"Иван","username":"ivan_petrov"},"payload":"promo_summer2025"}
  Ключевые поля: update_type === "bot_started", payload (или null), user, chat_id.

Управление ботом в кабинете
  Изменить можно все настройки, кроме ника: Чат-боты → выбор бота (имя в панели) → значок настроек → сохранить → повторная модерация; до её прохождения для пользователей отображается прежний вариант.
  Групповой чат: Чат-бот и мини-приложение → Настроить → разрешить/запретить добавление в группы → Сохранить.
  Где взять токен: Чат-боты → нужный бот → Интеграция → Получить токен (поле с токеном). Обновить: там же, значок обновления у поля.
  Удаление бота: настройки → Удалить бота — необратимо, клиенты потеряют доступ.

Мини-приложение
  После успешной модерации бота можно подключить мини-приложение — см. документацию мини-приложений MAX. Вопросы — раздел FAQ в доке.

Обзор API
  API MAX — HTTPS-интерфейс для ботов. Методы: GET (чтение), POST (создание, в т.ч. отправка сообщений), PUT/PATCH/DELETE — по смыслу операции. Ответ — JSON; смотрите также HTTP-код (200, 400, 401, 404, 405, 429, 503).
  Для обновлений бота: Long Polling — разработка/тест; в production — Webhook (только HTTPS). Ориентир нагрузки: до ~30 rps на platform-api.max.ru.

POST /messages — отправить сообщение (автопост анонсов на сайте)
  Тело запроса — JSON-объект NewMessageBody:
    text (string, nullable) — новый текст сообщения, до 4000 символов
    attachments (AttachmentRequest[], nullable) — вложения сообщения; если пусто, все вложения будут удалены
    link (object NewMessageLink, nullable) — ссылка на сообщение
    notify (boolean, optional) — по умолчанию true; если false, участники чата не получают уведомления о сообщении
    format (TextFormat, optional, nullable) — enum: "markdown" | "html"; если задан, поле text форматируется соответственно (подробности — раздел «Форматирование» в доке MAX)

  Пример объекта (поля опциональны, кроме необходимых для вашего сценария):
  {
    "text": "string",
    "attachments": [{ "...": "..." }],
    "link": { "...": "..." },
    "notify": true,
    "format": "markdown"
  }

  Вызов (анонс с сайта шлёт в основном text): 
    curl -X POST "https://platform-api.max.ru/messages?chat_id={chat_id}" \
      -H "Authorization: {token}" -H "Content-Type: application/json" \
      -d '{"text":"...","notify":true}'

GET /me — информация о боте по токену
  Метод идентифицирует бота через access_token. В ответе объект пользователя с полями бота (BotInfo): идентификатор, имя, ник, активность, описание, аватар и т.д.

  Пример:
    curl -X GET "https://platform-api.max.ru/me" -H "Authorization: {access_token}"

  Поля результата (основные):
    user_id (int64) — id пользователя или бота
    first_name (string) — отображаемое имя
    last_name (string, optional) — фамилия; для ботов обычно не возвращается
    username (string, nullable) — ник бота или публичное имя пользователя
    is_bot (bool) — true для бота
    last_activity_time (int64, optional) — последняя активность в MAX, Unix-время в миллисекундах; может отсутствовать из-за настроек приватности «онлайн»
    name (string, nullable) — устаревшее поле
    description (string, nullable, до 16000 символов)
    avatar_url (string, optional) — аватар уменьшенный
    full_avatar_url (string, optional) — аватар полного размера
    commands (BotCommand[], optional, до 32) — команды бота

GET /messages — сообщения из чата или по id
  Нужен ровно один из вариантов: chat_id ИЛИ message_ids.
  chat_id — массив сообщений из чата; порядок обратный хронологии (новые первыми).
  message_ids — один или несколько id через запятую.

  Примеры:
    curl -X GET "https://platform-api.max.ru/messages?chat_id={chat_id}" -H "Authorization: {access_token}"
    curl -X GET "https://platform-api.max.ru/messages?message_ids={id1},{id2}" -H "Authorization: {access_token}"

  Query-параметры:
    chat_id (int64, optional) — если не задан message_ids
    message_ids (строка через запятую, optional) — если не задан chat_id
    from (int64, optional) — начало периода (Unix timestamp)
    to (int64, optional) — конец периода (Unix timestamp)
    count (1…100, default 50) — сколько сообщений в ответе

  Результат: messages — массив Message[]

Подключение на lukinterlab.ru (автопост статей в MAX)
  В .env: MAX_BOT_TOKEN, MAX_CHAT_ID, MAX_AUTO_POST=True (в коде по умолчанию выключено, пока не включите).
  migrate → поле Post.max_posted_at; qcluster должен работать.
  Первая публикация статьи: анонс в чат, если max_posted_at пусто; повторные save опубликованной статьи в очередь MAX не ставят.
  Проверка бота: GET /me с тем же токеном, что в .env.

Полиморфность (asChild)
  Чтобы рендерить не дефолтный DOM-тег (например Button как <a> или как <Link> из react-router-dom), используйте asChild и передавайте один дочерний элемент-замену.
  Упрощённо: <Button> → <button class="...">; <Button asChild><a href="#">...</a></Button> → <a class="..." href="#">.
  С react-router-dom: <Button asChild><Link to="/home">...</Link></Button>.

Корнер-кейс asChild
  При конфликте пропсов: className, style и обработчики on* у родителя и ребёнка объединяются; в остальных случаях приоритет у пропсов родительского компонента. Пример: disabled у Button с asChild и у вложенного button — итоговые классы/стили сливаются по правилам библиотеки.

Кастомизация
  Два пути: переопределение CSS-переменных (токены дизайн-системы) и свойство innerClassNames у составных компонентов (например, отдельный class для внутреннего span с иконкой у Button).
  API кастомизации может меняться в мажорных версиях — ответственность за поддержку на стороне разработчика мини-приложения.

Примечание: текущий проект lukinterlab.ru — Django-бэкенд и автопост в MAX через HTTP API; MAX UI понадобится отдельному фронтенду (мини-приложение/React), если будете его делать.
